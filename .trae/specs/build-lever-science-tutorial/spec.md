# 小学科学杠杆实验教程网页规格

## 为什么
小学阶段的杠杆知识容易停留在名词记忆，需要通过“先猜想、再操作、用证据验证”的实验过程，让学生直观看见力、力臂与平衡之间的关系，并能把原理迁移到生活工具和人体动作中。

## 变更内容
- 新建一个面向小学生的单页科学教程网页，采用桌面优先、平板与手机自适应设计。
- 建立“认识杠杆 → 预测结果 → 动手实验 → 查看证据 → 识别类型 → 联系生活”的连续学习路径。
- 提供可交互杠杆实验台，可调整支点、用力点、阻力点以及用力和阻力大小。
- 覆盖杠杆五要素、杠杆原理、三种杠杆类型、生活中的杠杆工具和人体中的杠杆。
- 提供即时实验动画、力矩计算、结果解释、答题反馈、生活工具视频、进度记录和重置能力。
- 视觉参考附图的双栏实验布局，但不直接复制其品牌、文案或界面。

## 影响
- 受影响规格：小学科学教学、杠杆交互实验、知识练习、响应式与无障碍体验
- 受影响代码：全新的 React/Vite 前端工程、教学内容数据、交互实验状态与样式
- 数据与服务：纯前端运行，不要求账号、后端、数据库或网络持久化

## 新增需求

### 需求：教学首页与学习导航
系统必须以实际可学习的教程界面作为首屏，而不是营销落地页。

#### 场景：学生进入网页
- **当** 学生首次打开网页
- **那么** 首屏必须清晰显示课程名称“杠杆实验室”、当前学习进度和“开始探索”入口
- **并且** 首屏必须能直接看见或触达杠杆实验装置

#### 场景：学生切换学习章节
- **当** 学生选择“认识杠杆”“动手实验”“杠杆类型”“生活应用”中的任一章节
- **那么** 页面必须滚动或切换到对应内容
- **并且** 当前章节必须具有清晰的选中状态

### 需求：杠杆五要素
系统必须用图示与简短说明呈现杠杆及其五要素：支点、用力点、阻力点、用力臂和阻力臂。

#### 场景：查看五要素
- **当** 学生查看杠杆结构图
- **那么** 图中必须以不同颜色和标签标识支点、用力点、阻力点、用力臂和阻力臂
- **并且** 点击或悬停任一标签时，必须突出对应部位并显示适合小学生理解的定义

#### 场景：检查要素理解
- **当** 学生完成五要素学习
- **那么** 系统必须提供至少一道图中定位或配对练习
- **并且** 提交后立即显示正确答案与解释

### 需求：杠杆原理
系统必须说明并演示杠杆平衡条件“用力大小 × 用力臂 = 阻力大小 × 阻力臂”，并将两侧乘积称为力矩，避免仅给出抽象公式。

#### 场景：平衡实验
- **当** 用力一侧的力矩与阻力一侧的力矩相等
- **那么** 杠杆必须呈水平状态
- **并且** 证据区必须显示两侧计算过程和“力矩相等，所以平衡”

#### 场景：用力一侧占优
- **当** 用力一侧的力矩大于阻力一侧的力矩
- **那么** 杠杆必须以动画向用力点一侧倾斜
- **并且** 证据区必须指出哪一侧力矩更大以及差值

#### 场景：阻力侧占优
- **当** 用力一侧的力矩小于阻力一侧的力矩
- **那么** 杠杆必须以动画向阻力作用的一侧倾斜
- **并且** 证据区必须指出哪一侧力矩更大以及差值

### 需求：先猜再验证的交互实验
系统必须采用“设置条件 → 作出猜想 → 运行实验 → 查看证据”的顺序，避免在学生猜想前直接泄露结果。

#### 场景：设置实验
- **当** 学生调整实验参数
- **那么** 系统必须允许在有效刻度范围内调整支点位置、用力点、阻力点、用力大小和阻力大小
- **并且** 用力点与阻力点不得与支点重合，所有位置和数值必须清晰可读

#### 场景：提交猜想
- **当** 学生选择“左边下沉”“保持平衡”或“右边下沉”
- **那么** “运行实验”按钮必须变为可用
- **并且** 在运行前不得展示最终倾斜方向和力矩比较结论

#### 场景：运行实验
- **当** 学生点击“运行实验”
- **那么** 杠杆必须根据力矩结果产生平滑、可理解的倾斜或平衡动画
- **并且** 系统必须显示猜想是否正确、左右力臂、左右力矩及文字解释

#### 场景：修改已完成实验
- **当** 学生在查看结果后修改任一实验参数
- **那么** 上一次猜想和结果必须失效
- **并且** 页面必须回到等待猜想状态

#### 场景：重置实验
- **当** 学生点击重置按钮
- **那么** 所有参数、猜想、动画和证据必须恢复到默认状态

### 需求：三种杠杆类型
系统必须讲解省力杠杆、费力杠杆和等臂杠杆，并通过支点、用力点、阻力点的相对位置及力臂关系帮助学生判断。

#### 场景：学习类型
- **当** 学生选择一种杠杆类型
- **那么** 页面必须展示该类型的力臂关系、特点、典型用途和至少两个生活实例
- **并且** 实验台必须可加载一个对应的预设状态用于验证

#### 场景：判断类型
- **当** 学生完成类型学习
- **那么** 系统必须提供至少三道判断题，覆盖三种类型
- **并且** 每题必须在作答后解释判断依据，而不只显示对错

### 需求：生活中的杠杆
系统必须介绍常见杠杆工具，并说明每个工具的支点、用力点、阻力点及所属类型。

#### 场景：浏览生活工具
- **当** 学生进入生活应用章节
- **那么** 页面必须至少展示剪刀、钳子、开瓶器、核桃夹、镊子、筷子、跷跷板、天平八种工具
- **并且** 每个工具必须具有清晰可辨的视觉素材、名称和类型

#### 场景：探索工具结构
- **当** 学生选择一个工具
- **那么** 系统必须展示其支点、用力点和阻力点
- **并且** 用一句简明说明解释它为什么属于对应杠杆类型

#### 场景：观看工具使用视频
- **当** 学生选择任一生活工具的“看它怎么工作”入口
- **那么** 页面必须在当前学习上下文中播放与该工具实际使用方式匹配的短视频
- **并且** 剪刀、钳子、开瓶器、核桃夹、镊子、筷子、跷跷板、天平八种工具必须各自匹配对应视频，不得复用无关内容

#### 场景：控制视频播放
- **当** 视频区域出现在页面中
- **那么** 视频不得自动播放，必须提供播放、暂停、进度、音量和全屏等原生或等效控制
- **并且** 必须提供工具名称、杠杆观察重点和简短文字摘要，帮助学生带着问题观看

#### 场景：视频不可播放
- **当** 视频加载失败、网络不可用或浏览器不支持播放
- **那么** 页面必须保留工具图片、要素标注和文字说明
- **并且** 显示简洁的不可播放提示，不得阻断其他教学内容和实验功能

#### 场景：视频内容安全
- **当** 页面加载生活工具视频
- **那么** 视频必须来源明确、允许网页使用、内容适龄且不含广告、账号引导或无关推荐
- **并且** 视频必须具有可读字幕，或提供含等价信息的文字说明

### 需求：人体中的杠杆
系统必须以适龄方式介绍人体运动中的杠杆，明确骨是杠杆、关节是支点、肌肉作用处是用力点、身体或外物作用处是阻力点。

#### 场景：浏览人体案例
- **当** 学生查看人体杠杆章节
- **那么** 页面必须至少介绍踮脚、屈肘举物和抬头三个动作
- **并且** 每个动作必须标出支点、用力点、阻力点和对应杠杆类型

#### 场景：切换人体动作
- **当** 学生切换动作
- **那么** 图示标注和说明必须同步更新
- **并且** 不得使用令人不适或超出小学课程理解范围的解剖细节

### 需求：学习总结与反馈
系统必须让学生看见学习进展，并在完成主要内容后获得简洁总结。

#### 场景：完成学习活动
- **当** 学生完成知识点、实验或练习
- **那么** 对应进度必须即时更新
- **并且** 页面刷新前必须保留当前会话中的完成状态

#### 场景：查看学习总结
- **当** 学生完成全部核心活动
- **那么** 页面必须展示包含“认识五要素、会用力矩判断、能辨别三种杠杆、能发现生活杠杆”的总结
- **并且** 提供重新挑战实验和练习的入口

### 需求：视觉与交互设计
系统必须采用适合小学科学课堂的“实验记录册 + 实体教具”视觉方向，清晰、活泼但不过度幼稚。

#### 场景：桌面端浏览
- **当** 视口宽度适合桌面设备
- **那么** 实验页必须采用左侧大实验台、右侧实验控制与证据区的双栏结构
- **并且** 杠杆、刻度和受力标记必须占据主要视觉焦点

#### 场景：移动端浏览
- **当** 视口宽度较窄
- **那么** 实验台与控制区必须按学习顺序垂直排列
- **并且** 所有按钮、选项和滑块必须适合触控，文字不得溢出或互相遮挡

#### 场景：视觉资产展示
- **当** 页面展示生活工具或人体动作
- **那么** 必须使用真实可辨识、与内容对应的位图视觉素材
- **并且** 网页图片必须使用规定的文生图接口地址生成，不得使用占位图或无关图库图片

### 需求：可访问性与教学安全
系统必须保证核心操作可通过键盘和触控完成，并为色觉差异和动画敏感用户提供可理解的体验。

#### 场景：仅使用键盘操作
- **当** 用户通过 Tab、方向键、空格或回车操作
- **那么** 导航、参数调整、猜想、运行实验和练习必须可完成
- **并且** 焦点状态必须清晰可见

#### 场景：颜色无法区分
- **当** 用户不能依赖颜色辨别内容
- **那么** 用力点、阻力点和结果必须同时使用文字、图标或形状编码

#### 场景：减少动态效果
- **当** 系统检测到“减少动态效果”偏好
- **那么** 倾斜与转场必须改为即时或弱动画呈现

### 需求：技术范围
系统必须作为无需登录和后端的前端单页应用运行，优先使用 React、TypeScript 和 Vite，并将教学内容与交互逻辑分离。

#### 场景：离线核心学习
- **当** 页面资源已完成首次加载
- **那么** 核心概念、实验计算、练习和进度必须在浏览器端完成
- **并且** 除生活工具视频资源外，不得依赖远程业务接口或账号系统

#### 场景：实验计算
- **当** 任意合法参数组合被提交
- **那么** 结果必须由统一的力矩计算逻辑得出
- **并且** 动画方向、文字结论、答案判定和证据数值必须使用同一计算结果

## 修改需求
无。

## 移除需求
无。
